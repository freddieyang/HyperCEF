# HyperCEF

HyperCEF is the reference implementation of **Hypergraph-Based Context Encoding and Fusion for Chassis-Based Reaction Feasibility Prediction**. It produces two complementary outputs for a query reaction:

Repository: <https://github.com/freddieyang/HyperCEF>

- **chassis-independent feasibility**, estimated from the unordered set of molecular participants; and
- **chassis-based feasibility**, estimated from molecular information, a chassis reaction hypergraph, and reference-conditioned calibration.

The public interface uses the name `HyperCEF` throughout. The primary paper configuration uses 2048-bit Morgan fingerprints, two hypergraph-convolution layers, hidden width 768, two-head participant-set attention, and a fixed molecular-to-chassis residual scale of 0.5.

## Installation

Python 3.10 or later is recommended. Install PyTorch for the CUDA version available on your system, then install this package:

```bash
python -m pip install -e .
```

For a CPU-only environment, the dependencies in `pyproject.toml` are sufficient. GPU users should follow the PyTorch and PyTorch Geometric installation instructions for their CUDA toolkit before running the command above.

## Input format

`metabolites.csv` contains one molecular structure per row:

```text
metabolite_id,smiles
glucose,OCC1OC(O)C(O)C(O)C1O
```

`reactions.csv` assigns an unordered participant set to one of the three training groups:

```text
reaction_id,group,metabolite_ids
native_1,native,glucose;pyruvate
absent_1,chassis_absent,pyruvate;ethanol
perturbed_1,perturbed,glucose;malate
```

The allowed groups are:

- `native`: present in the selected chassis; positive for both outputs;
- `chassis_absent`: biochemically documented but absent from the selected chassis; positive for the molecular output and negative for the chassis output; and
- `perturbed`: invalid participant-set controls; negative for the molecular output and not assigned a chassis label.

Reaction direction and stoichiometric coefficients are not used by the model. Dataset construction should therefore apply the same metabolite-identity normalization and record filtering to every group before training.

## Quick start

The files under `examples/` illustrate the schema and are intended only for a functional check; they are not paper benchmark data.

```bash
python scripts/prepare_data.py \
  --metabolites examples/metabolites.csv \
  --reactions examples/reactions.csv \
  --output examples/prepared

python scripts/train.py \
  --data examples/prepared \
  --config configs/paper.json \
  --output runs/example

python scripts/predict.py \
  --data examples/prepared \
  --checkpoint runs/example/model.pt \
  --group chassis_absent \
  --output runs/example/predictions.csv
```

For a participant-set-grouped evaluation, use:

```bash
python scripts/cross_validate.py \
  --data path/to/prepared_chassis \
  --config configs/paper.json \
  --folds 5 \
  --output runs/chassis_cross_validation
```

The cross-validation command rebuilds the chassis incidence matrix from the native training reactions in each fold. Held-out native reactions are consequently excluded from message passing and from the native reference set.

## Python API

```python
from hypercef import HyperCEF, load_prepared_dataset, predict

dataset = load_prepared_dataset("path/to/prepared_chassis")
model = HyperCEF(
    in_channels=dataset.x.shape[1],
    hidden_channels=768,
    out_channels=1,
    dropout=0.05,
    num_layers=2,
    heads=2,
)
model.fit_topology_boundary_prototypes(
    dataset.x,
    dataset.edge_index,
    dataset.native,
    dataset.chassis_absent,
)
scores = predict(model, dataset.x, dataset.edge_index, dataset.native)
```

`scores["chassis_independent"]` and `scores["chassis_based"]` contain probabilities in the same order as the supplied reaction list.

## Reproducing the primary benchmark

The repository contains the primary HyperCEF model, its two-term objective, the preprocessing schema, metric implementation, and participant-set-grouped cross-validation runner. To reproduce the six-chassis benchmark, construct one prepared dataset per genome-scale metabolic model using the data sources and filtering rules described in the manuscript and Supplementary methods. The benchmark data are not included in the small example directory.

Use `configs/paper.json` unchanged for the reported primary architecture and optimization settings. Record the software environment and retain the fold-level prediction files generated by `scripts/cross_validate.py` when producing aggregate tables or plots. The separately identified auxiliary-objective analyses in the Supplementary information are outside this compact release and should not be conflated with the primary benchmark configuration.
